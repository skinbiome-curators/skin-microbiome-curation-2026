# 데이터 분야 심사위원 사전 읽기 — 2조 (slides_v3, s00–s22)

관점: 통계 · ML · 데이터 엔지니어링. 미생물 · 피부 · 규제 · 사업은 잘 모름. 화면에 적힌 것만 근거.

## 장별 메모

### s00 표지
- 한 줄: 민감 피부 화장품의 마이크로바이옴 인체 시험을 "설계 · 판정"해 주는 서비스(중소 화장품사 대상).
- 막힘:
  - "데이터의 함정" — 어떤 함정인지 아직 모름(배치 효과? 표본 수?). 부제의 핵심어인데 정의 없음.
  - "큐레이션 방향: 예방 · 관리" — 대회 분류 같은데 무엇을 예방 · 관리하는지 모름(대회 취지를 모르는 사람에게 설명 없는 태그).
  - "판정" — 무엇을 판정하는지(제품 효과? 시험 설계의 적합성?) 아직 불명.
- 5초: 예(서비스 성격은 들어옴). 단 "함정"이 무엇인지는 안 들어옴.

### s01 결론부터 · 한눈에 보는 제안
- 한 줄: 문제(시험 설계가 잘못되면 효과 판단 불가) → 기술(다섯 관문 + 설계 점검) → 제안(설계 점검 → CRO 시험 → 판정 · 문장).
- 막힘:
  - "다섯 관문" — 다섯 개가 무엇인지 없음. 그런데 바로 "관문 ①②를 코호트 11개에 적용" — 왜 다섯 중 둘만? ③④⑤는?
  - "07 = 수업 자료 중 공개 화장품 인체 시험" (각주) — 본문에 "07"이라는 말이 없음. 설명 없는 내부 번호가 각주에만 등장.
  - "시점마다 시퀀싱 런이 달라" — 데이터 쪽으로는 바로 이해됨(시점과 배치가 완전 교락). 다만 "시점–런 겹침"이라는 자체 용어로 바뀌어 불림.
  - "Malassezia restricta 신호" — 무엇인지 모름(균 이름?). "신호"가 유의한 차이인지, 효과 크기인지, 몇 개 코호트에서 재현됐는지 없음.
  - "바로 쓰는 문장" / "문장은 데이터가 받치는 만큼" — 무슨 문장인지 모름(광고 문구? 보고서 문장?).
  - "CRO" — 임상시험 대행기관으로 추정. 화면엔 풀이 없음.
  - "88%는 종사자 10명 미만" — 문제 박스에 들어 있지만 "설계에서 갈린다"와의 연결이 한 단계 빠짐(작은 회사 → 분석 인력 없음, 이라는 연결은 내가 채워야 함).
- 5초: 아니오. 세 칸 구조는 보이는데 "관문" · "문장"이 무엇인지 몰라서 제안의 실체가 안 잡힘.

### s02 10/10 최종 피칭 이후 바뀐 점
- 한 줄: 지난 발표(10/10) 대비 강조점 · 고객 · 결과물 · 매출 구조를 바꿨고, 각 변경에 심사 피드백을 대응시킴.
- 막힘:
  - 10/10 발표를 본 적이 없어서 왼쪽 열("작은 데이터의 판정 결과", "측정비 0", "채택 · 후속 · 조건부 · 보류")이 맥락 없이 읽힘.
  - "판정이 맨 위에 — 설계 점검 결과 · 문장별 ✅△❌" — 아직 "문장"을 모르니 무슨 표가 나온다는 건지 모름.
  - "BMI처럼 결과를 명확하게" — 피드백 인용이라 이해는 되나, 이 덱에서 어떻게 반영됐는지 여기선 안 보임.
  - "입력 경로 · 처리 경로 · 건당 원가" — 데이터 엔지니어 입장에선 반가운 항목. 뒤에서 나오길 기대.
- 5초: 아니오. 7행 × 4열 표, 두 번째 장에 '변경 이력'이 오면 처음 보는 심사위원에겐 무엇이 바뀌기 전의 무엇인지가 없음.

### s03 주제 선정 배경 — 민감 피부와 피부 미생물
- 한 줄: 민감 피부는 흔한데(자기보고 71% / 40%) 객관적으로 가를 기준이 없고, 시장엔 마이크로바이옴 시험이 이미 팔리고 있으니 "피부 미생물이 객관적 지표가 되나?"를 묻는다.
- 막힘:
  - "자통 시험" — 모르는 용어. 설명(젖산 바르고 따가움 답함)이 붙어 있어 대략 이해.
  - "16S 균 분류 프로파일" — 16S가 무엇인지 화면에 없음(시퀀싱 방식 이름으로 추정).
  - "기능성 보고" · "식약처 기능성 보고 자료 집계(팀 계산 · 하한)" — 규제 용어. "하한"이 무엇의 하한인지 불명.
  - 질문 "객관적 지표로 사용 가능할까?" — s02에서 '진단 — 지표 판정'을 버리고 '예방 · 관리'로 바꿨다고 했는데 여기 질문은 지표(진단) 쪽. 방향이 바뀐 건지 질문만 남은 건지 헷갈림.
  - 71% · 40%가 자기보고라는 점은 정직하게 적혀 있음. 다만 "객관 기준 없음"의 근거와 "그래서 미생물"의 연결은 질문으로만 남음.
- 5초: 예(큰 숫자 + 하단 질문 막대).

### s04 데이터셋 — 필요를 따라 고른 자료 7곳
- 한 줄: 7개 공개 자료(11개 코호트, 16S 1,308 · ITS 596 시료)를 각자 다른 목적(라벨 · 큰 표본 · 화장품 시험 · 반복측정 · 이식성)으로 골랐고, 자료 간 값을 합치지 않는다.
- 막힘:
  - 행 이름이 "03 · 07 · 15 · 01 · 02 · 16" — 수업 자료 내부 번호. 각주에 "수업 자료 번호"라고만 있음. s01 각주의 "07"이 여기서야 풀림. 이후 장에서도 이 번호로 부르면 따라가기 어려움.
  - "7곳" — 자료를 '곳'으로 셈. 기관 7곳인지 데이터셋 7개인지 순간 헷갈림.
  - "11개 코호트(세균 7 · 진균 4)" — 7개 자료가 어떻게 11개 코호트로 쪼개지는지(어느 자료에 진균이 있는지) 표에 직접 안 나옴(03만 '세균 + 진균' 표시).
  - "ITS" — 설명 없음(진균용 마커로 추정).
  - "이식성" — 다른 자료로 옮겨도 되는지(일반화)로 추정. "④ 판별력" — 관문 번호가 정의(s05)보다 먼저 등장.
  - "EGA" — 설명 없음.
- 데이터 관점 메모: 민감/비민감 라벨이 있는 자료가 **03 하나, n = 42(23 / 19)**. 판별 주장은 이 42명에 달려 있음. "값을 합치지 않고 각 자료 안에서만 판정"은 배치(채취법 · 증폭 구간) 차이를 아는 결정이라 좋음.
- 5초: 예(제목 + 7 / 11 큰 숫자). 단 표의 행은 번호로 불려서 '어느 자료가 무엇'인지 바로 안 붙음.

### s05 분석 기술 — 함정을 하나씩 막는 다섯 관문
- 한 줄: 다섯 관문(① 검출 · 오염, ② 혼란변수 · 조성 데이터, ③ 분류 이름 일치, ④ 판별력, ⑤ 종 수준 확인) + 화장품 시험용 '설계 점검'(시점–런 교락 등).
- 막힘:
  - "심도" — 시퀀싱 깊이(read 수)로 추정. "얕게 읽은" 도 같은 뜻인 듯.
  - "로그비" — log-ratio로 이해(조성 데이터 처리). 데이터 사람에겐 좋은 신호.
  - "BLAST" · "속 / 종" · "상재 종" · "병원성" — BLAST는 서열 정렬 도구 정도로 앎. "상재"는 모르는 말.
  - "구간이 50%에 걸치면" — AUC 0.5를 50%로 표기. AUC를 %로 쓰면 '정확도 50%'로 읽힐 수 있음.
  - 관문 제목이 질문형("늘 잡히나 · 흔들리나 · 이름표 믿나 · 가르나 · 종까지 말하나") — 재미있지만 표준 용어(검출 · 혼란변수 · 분류 · 판별 · 종 수준)가 같이 없으면 데이터 사람은 매핑을 스스로 해야 함.
  - s01은 "관문 ①②를 코호트 11개에 적용", 여기는 "①②③⑤는 자료 전반에 그대로". ③⑤는 11개에 돌렸는지 안 돌렸는지 불명.
  - "통과 기준" — 사람이 정했다는데 ① · ② · ③ · ⑤의 수치 기준(검출률 몇 % 이상 등)은 이 장에 없음.
- 데이터 관점 메모(좋음): 깊이–상대풍부도 상관으로 오염 의심, 블랭크 대조, 조성 데이터 → 로그비, 나이 · 피지 보정, **사람 단위** 부트스트랩 4,000회, CI가 0.5를 포함하면 보류. 방법 선택이 타당함.
- 데이터 관점 메모(빠짐): ④에서 몇 개 분류군을 동시에 봤는지, **다중검정 보정**을 했는지 없음. n = 42에서 수십~수백 개 균을 보면 하나쯤 AUC CI가 0.5를 벗어나는 건 우연으로도 나옴.
- 5초: 아니오. '다섯 관문'이라는 틀은 들어오지만 5열 × (함정 · 점검) 문단 + 띠 2개라 각 관문이 무엇을 거르는지는 못 읽음.

### s06 주요 결과 ① 후보 4개와 Malassezia 신호
- 한 줄: 807 세균 속 · 234 진균 속에서 라벨을 보지 않는 세 질문으로 후보 4개를 남겼고, 그중 Malassezia만 민감/비민감을 가름(AUC 85%, 비민감 중앙값 84.2% vs 민감 36.4%).
- 막힘:
  - "AUC 85%" 큰 글씨 — AUC를 %로 크게 쓰면 처음엔 '정확도 85%'로 읽힘. 옆 설명("1명씩 뽑으면 더 많을 확률")으로 풀리긴 함.
  - "신뢰 구간이 50%에서 떨어져 있음" — **구간 숫자가 없음.** 하한이 0.55인지 0.75인지에 따라 무게가 완전히 다름.
  - "상대풍부도" — 무엇에 대한 상대(전체 진균 중 비율)인지 화면에선 추정해야 함.
  - "속" · Cutibacterium 등 학명 — 생물 쪽은 모름. 판단에 지장은 크지 않음.
  - "질문 셋"의 첫째가 "늘 잡히나" — s05 관문 ① 이름과 같아서 관문 = 질문인지, 관문 ① · ② 를 줄여 쓴 건지 헷갈림.
- 데이터 관점 메모(좋음): 후보 선정을 **라벨 없이**(순환 방지) 해서 판별 검정은 4개로 줄임 → 다중검정 우려가 크게 줄어듦. "효과 없음이 아니라 42명으론 판단 불가 · 군당 65명이면 ±0.10" — 정밀도 기반 표본 크기 제시가 성숙함.
- 데이터 관점 메모(의문): 방향이 '민감 쪽에서 Malassezia가 **적다**' — 반직관인지 아닌지 나는 판단 못 함. 화면에 해석 한 줄이 없음.
- 5초: 예(막대 두 개 + 85%). 단 85%가 무엇의 85%인지는 5초 뒤에 풀림.

### s07 주요 결과 ② 교란 점검과 종 수준
- 한 줄: 나이 · 피지 · 계산 방식(로그비)을 바꿔도 Malassezia 신호가 유지되고, 진균은 종(M. restricta)까지 확인 가능하나 세균 Staphylococcus는 짧은 16S 구간으로 종 구분 불가.
- 막힘:
  - 같은 장에서 AUC를 **0.65 → 0.88**(소수)과 **85% → 82%**(퍼센트)로 섞어 씀. 같은 지표인지 순간 의심.
  - 관문 이름이 장마다 바뀜: s05 "② 흔들리나" → s07 제목 "교란 점검" → 소제목 "다른 요인 때문은 아닌가". 같은 것을 세 이름으로 부름.
  - "리드" · "우점종" · "qPCR" · "절대량" · "NCBI BLAST" · "core_nt" · "ASV0006" — qPCR · 우점종 · ASV는 모름. 각주의 파일명은 심사위원에게 의미 없음.
  - "ρ = −0.98" — 무엇과 무엇의 상관인지(Malassezia 비율 vs 진균 다양성) 문장 안에서 겨우 읽힘.
- 데이터 관점 메모(좋음): 나이 단독 0.65 vs 나이 + Malassezia 0.88, **LOO 0.58 → 0.85** 동시 제시. 피지 AUC 0.49. 로그비 재계산 85 → 82%. 비율 자료의 한계(다양성과 ρ = −0.98, 음성대조 없음)를 스스로 적음. BLAST 375/375 · 상위 50개 동률로 "종 구분 불가"를 증명 — 한계를 데이터로 보여준 점이 좋음.
- 데이터 관점 메모(빠짐): 0.88 · 0.85 의 신뢰구간 없음. 로지스틱 회귀에서 Malassezia 계수 · p 값 없음. 42명에서 LOO만으로는 분산이 큼 — 반복 CV나 구간 필요.
- 5초: 아니오. 하단 결론 막대("우선 잴 후보 = M. restricta")는 들어오지만, 좌우 두 주제(교란 · 종 수준)가 한 장에 있어 '왜 믿을 만한지'는 5초에 안 들어옴.

### s08 주요 결과 ③ 공개 화장품 시험 재분석 — 시료 75개 · 결론 불가
- 한 줄: 공개된 화장품 인체 시험(25명 · 0/2/4주)을 다시 보니 0주와 4주가 서로 다른 시퀀싱 런이라 제품 효과와 런 차이가 완전히 겹쳐 있고, 0주에만 몰린 6속을 빼면 원 논문의 '증가'가 사라짐 → "결론 불가".
- 막힘:
  - "머리줄" — FASTQ header를 우리말로 바꾼 듯. 데이터 사람은 'header'가 더 빨리 읽힘.
  - "런 242 · 241 · 244 · 243" — 런 번호 자체는 의미 없지만 그림이 잘 보여줌. 문제없음.
  - "0주에만 몰린 6속"(각주: Wolbachia · Akkermansia · Bacteroides …) — 왜 이 6개가 '오염 또는 런 탓'으로 의심되는지 생물학적 이유는 나는 모름. 화면 근거는 '0주에만 몰림' 하나.
  - "검출 문턱을 바꾸면 남기도 함" — 어떤 문턱에서 남는지 숫자가 없음.
  - "07"(각주) — 다시 내부 번호.
- 데이터 관점 메모(좋음): 배치(런)와 처리(시점)의 **완전 교락**을 원자료 헤더에서 찾아낸 것 — 이 덱에서 가장 설득력 있는 장. 분모 효과(조성 데이터 아티팩트), Holm 보정 p, 문턱 민감도까지 정직하게 적음. "판정은 계산 전에 규칙으로 정해짐"(사전 규칙)도 좋음.
- 5초: 예. 제목 오른쪽 "결론 불가" + 런 상자 그림 + 하단 막대로 바로 들어옴.

### s09 검증 — 이 결과를 믿을 수 있는 이유
- 한 줄: 기준은 사람이 미리 정하고(사전 규칙 · 사후 규칙 구분), 숫자는 별도 코드로 원자료에서 재계산(시드 고정 · 다른 PC 재현)하며, 검수 과정 자체를 일부러 심은 오류로 시험했다.
- 막힘:
  - "검수" · "실증" · "등록" — '검수'는 QA/리뷰, '등록'은 사전등록(pre-registration)으로 추정. 데이터 사람에겐 영어 원어가 더 빠름.
  - **"결과를 본 뒤 정리한 후보 규칙은 '사후 규칙'이라고 밝힘"** — 어떤 규칙이 사후인지 이 장에 없음. s06 후보 선정 세 질문이 사후 규칙이라면 '라벨 안 보고 골랐다(순환 방지)'의 무게가 달라짐. 가장 중요한 단서인데 한 줄로 지나감.
  - "잡아서 고친 오류: 15 계절 '미국 · 중국' → 홍콩 · 74명 계산 경로 · OTU → ASV" — 무엇이 틀렸었고 결과에 영향이 있었는지 모름. "74명"은 덱 어디에도 없던 숫자. "OTU → ASV"는 모르는 약어.

- 5초: 예(세 카드 제목만으로 들어옴).

### s12 서비스 개요 — 누구에게, 어떤 경로로
- 한 줄: 고객 = 분석 체계 없는 중소 원료사(데이터 있음 → 판정부터) · 중소 브랜드(데이터 없음 → 설계부터), 대기업 제외. 판매는 피부 CRO 협력이 1순위, EU · 영국 수출이 2순위, 첫 분야는 민감 피부 라인.
- 막힘:
  - "판정 입구" · "설계 입구" — 팀 내부 용어. 2×2 표 덕에 뜻은 짐작됨.
  - "EU · 영국 등록 기관 묶음" — 무엇을 묶는지(어떤 기관인지) 모름. "PIF" · "제11조 ②(d)" — 규제라 판단 불가.

  - "설계 요구서" — 새 산출물 이름. s13 · s14에서 나오긴 함.
  - 상단 막대 문장이 두 줄로 길어서 5초에 다 못 읽음.
- 5초: 반쯤(예에 가까움). 2×2 고객 표는 바로 들어오나 판매 경로 2순위는 안 들어옴.

### s13 상품 구성 — 네 가지 장치
- 한 줄: ① 무료 설계 점검(입구) → ② 설계 · 시험 · 판정 CRO 묶음(핵심, 우리 몫 건당 약 50만 원 · 가정) → ③ 판정 + 결과물 세트(원료사) → ④ '아직 안 됨'이면 다음 설계 무료(재구매 고리).
- 막힘:
  - "장치" — 상품 구성요소를 '장치'라 부름. 하드웨어처럼 들림.
  - 원 숫자 ①②③④가 여기선 상품 번호. s05의 관문 ①–⑤와 같은 기호라 "③ 결과물 세트"를 읽을 때 '관문 ③(이름표)'와 순간 겹침.
  - "④ → ②" 고리 — 이해됨.
  - "무료 빠른 데이터 점검 — FASTQ 머리줄 + 시료표만으로" — 데이터 엔지니어 입장에선 가장 구체적인 문장. 다만 CRO · 공개 저장소가 헤더를 바꿔 쓰면(런 정보 없음) 어떻게 하는지 없음.
- 데이터 관점 메모(의문): 판정이 '아직 안 됨'일수록 다음 시험 · 다음 판정 매출이 생기는 구조 → **판정자가 판정 결과에 이해관계를 갖는 구조**로 읽힐 수 있음. s14의 '규칙 공개 · 계산 전 확정'이 완충이긴 한데 이 장에서 직접 다루지 않음.
- 5초: 아니오. 네 카드 제목은 보이나 본문 · 가격 · 하단 두 상자까지 정보가 많음. "가정" 표시는 정직함.

### s14 결과물 예시 ① 시험 전 설계 점검 리포트(견본, 07 대상)
- 한 줄: 07 시험에 리포트를 실제로 적용한 견본 — 판정 "아직 안 됨", 걸린 항목 4개, 낭비 추정 약 421만–1,394만 원, 고친 설계 요구서 5개.
- 막힘:
  - **"시점마다 다른 시퀀싱 런 — 제품 효과와 처리 차이가 겹침"** — s08에서는 "제품 효과와 **런** 차이가 겹침". '처리'는 곧 제품이라 문장이 자기모순으로 읽힘. 오기로 보임.
  - "모의 군집" · "PCR" · "qPCR" — 모르는 말(모의 군집 = 정답을 아는 표준 시료로 추정).
  - "07 수준 흔들림이면 총 26–40명" — 어떤 효과 크기 · 유의수준 · 검정력을 가정했는지 없음. "부록 A5"는 받은 23장에 없음. s06의 '군당 65명'과 숫자가 나란히 기억돼 혼동(목적이 다른 계산인지 설명 없음).
  - "07 수준 흔들림" — s04는 흔들림 기준을 15 계절에서 잡는다 했는데 여기는 07 기준.
  - "최고 등급(근거로 사용 가능)의 기준은 설계 중 — 지금 최고는 '조건부'" — 3단계 판정의 맨 윗단이 아직 정의 안 됐다는 뜻. 정직하지만, 판정 서비스의 핵심 규칙이 미완이라는 신호.
- 데이터 관점 메모(좋음): 낭비 계산의 산식(75 × 단가, 출처 · 환율 · 날짜)이 투명하고 '시퀀싱만 센 하한'이라 밝힘. 입력 지문 SHA-256 · 시드 고정 — 재현성 설계가 구체적.
- 5초: 예(빨간 '아직 안 됨' + 판정 문장).

### s15 결과물 예시 ② 시장별 문장 카드
- 한 줄: 같은 07 데이터로 쓰고 싶은 광고 · 표시 문장 4개를 시장별(EU · 영국 / 국내)로 ✅ · △ · ❌ 판정한 견본.
- 막힘:
  - 여기서 비로소 s01부터 나온 **"문장" = 제품 광고 · 표시 문구(claim)** 라는 게 확실해짐. 이 장이 덱 앞쪽에 있었으면 s01 · s02가 바로 읽혔을 것.
  - "Probiotic" 행 — 이유 칸은 "미국 소송 쟁점"인데 열은 EU · 영국 / 국내뿐. 미국 열이 없음. "성분 확인"이 판정 값인지 할 일인지 불명.
  - "RP" · "PIF" · "상재균" — 규제 · 생물 용어(RP는 '책임자'로 풀어줌).
- 데이터 관점 메모(좋음): "S. epidermidis increased ❌ ← BLAST 375/375 · 6종 동률"처럼 분석 결과가 판정 이유로 그대로 이어짐. 근거 → 판정의 연결이 추적 가능.
- 데이터 관점 메모(빠짐): **✅가 나오는 예시가 하나도 없음.** s14에서 최고 등급 기준이 '설계 중'이라 했으니, 이 서비스가 긍정 판정을 내리는 모습은 아직 본 적이 없는 셈.
- 5초: 예(행 = 문장, 칸 = ❌ / △ 아이콘 — 구조가 바로 보임).

### s16 운영 구조와 건당 원가
- 한 줄: 입력(계획서 · CRO 균 표 · 시료표 · FASTQ 헤더) → 처리(지금은 CRO 균 표 그대로) → 판정 엔진 → 결과물, 계산 약 2분 · 사람 5–10시간 · 원가 17.5–35만 원 · 우리 몫 약 50만 원(가정).
- 막힘:
  - "판정 엔진 — 10/10 + 11월 규칙" · "E0 품질" — 날짜 · 내부 코드로 부르는 규칙 묶음. 무엇인지 모름.
  - "가. / 나. / 다." 경로 — 이해됨. "다. 자체 파이프라인 — 발표 뒤 과제" 정직.
  - "Wilcoxon · Holm" — 이해됨. 다만 s05에선 비율 대신 로그비라 했는데, 사용 전후 Wilcoxon을 무엇(비율? 로그비?)에 거는지 없음.
- 데이터 관점 메모(의문):
  - 기본 경로 "가. CRO 균 표 그대로"에서는 원시 서열이 없으니 관문 ③(분류 이름 일치) · ⑤(BLAST 종 확인), 그리고 ①의 일부(심도 상관)를 **돌릴 수 있는지** 불명. 엔진 칸엔 "관문 ①–⑤"라고 다 적혀 있음.
  - 고객마다 CRO 처리 방식이 다르면 균 표끼리 비교 불가 — '그 시험 안에서만 판정'이라고 선을 그은 건 좋음.
  - "개인 식별 정보 받지 않음(가명 ID)" — 원시 FASTQ를 받는 선택 경로에서 사람 DNA 서열이 섞이는지, 섞인다면 제거하는지 화면에 없음(생물 쪽은 내가 판단 못 함 — 질문으로 남김).
- 데이터 관점 메모(좋음): 원가 산식이 재현 가능(일당 × 일수, 출처 명시). 계산 시간 · 메모리 실측. s02에서 약속한 '입력 경로 · 처리 경로 · 건당 원가'가 실제로 나옴.
- 5초: 예(아래 큰 숫자 넷). 위 흐름도의 내용은 5초에 안 들어옴.

### s17 기존 서비스와의 차이
- 한 줄: 피부 CRO · 등록 대행 · 해외 인증 · 소비자 검사 · 광고 자문이 각각 비워둔 곳(설계 점검 · 원시 데이터 깊이 · 균 → 문장)을 채우며, 경쟁보다 붙는 모듈로 간다.
- 막힘:
  - 다시 ①②③ 원 숫자(세 번째 다른 용도).
  - "확인한 7곳 공개 페이지" — s04의 '자료 7곳'과 같은 '7곳'. 우연이지만 헷갈림.
  - "등록 대행 · 책임자(RP)" — 규제 쪽이라 판단 불가.
- 데이터 관점 메모(의문): "② 독립 — 시험하지 않은 쪽의 판정"을 내세우는데, s13에서는 **CRO와 한 가격으로 묶어 팔고**, s17에서는 **판정 모듈이 CRO 상품에 붙는다**. 판정자의 독립성이 어떻게 유지되는지(계약 구조 · 규칙 공개 외 장치) 설명이 없음. s13의 '아직 안 됨 → 재구매' 구조까지 합치면 이해충돌 질문이 나올 자리.
- 5초: 아니오. 5행 × 4열 표가 먼저 눈에 들어오고, 요점인 아래 세 상자는 그다음.

### s18 목표 고객과 시장 — 고객 수로 센 첫 시장
- 한 줄: 화장품 회사 15,342곳(88% 10명 미만) 중 마이크로바이옴 기능성 보고 137곳이 1순위 고객 풀, 원료사 8곳, CRO 해외 매출 증가 · EU/영국 수출 급증 → 민감 피부 라인 → EU · 영국 → 시험 전반으로 넓힘.
- 막힘:
  - "0.07 → 2.13억 원" — **어느 해에서 어느 해**인지 없음. "+179% · +293%"도 기준 기간이 '2026년 1–9월'이라고만(전년 동기 대비로 추정).
  - "(□)" — 각주의 "조사 단계(□)" 기호가 본문 어디에 붙었는지 못 찾음.
